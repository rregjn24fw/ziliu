# 字流 · 扩展设计（互动感增强 · 全离线优先）

> 本文档是本次扩展的**唯一主设计文档**。A 段（1~5 节）是互动感增强的落地规格；第 6 节是第二阶段的云同步 / 朗读 / 书签笔记 / 导出（现已实现）；第 7 节记录字的手感与英文适配。
>
> 本文件与代码一一对应，实现须**严格按本文执行**。

---

## 0. 目标与硬性约束

### 目标
在不推翻现有架构的前提下，为「字流」增加**文章互动感**：分支剧情（轻量文字游戏）+ 拟人陪伴角色，并支持用户**可选地**配置 AI 生成互动内容。

### 硬性约束（最高优先级）
1. **默认本地运行、不介入 AI**：生成器默认 `offline` 后端（模板/规则兜底），零网络、零依赖、零 API Key。`llm` / `local` 仅在用户显式配置后才启用。
2. **直接导入 `.txt` / `.epub` 即可离线运行**：复用现有 `js/importers.js`，不改动导入链路。所有新增互动能力在无网络、无 AI 时完整可用。
3. **不破坏现有阅读流**：无分支剧情的书，阅读行为与现在完全一致。
4. **风格一致**：沿用 IIFE + `window.XR` 命名空间 + CJS 守卫 + 纯函数可测；2 空格缩进、单引号、分号、中文注释。

## 2. 数据模型

### 2.1 Story（分支剧情，IDB store `stories`，keyPath `id`）

```js
{
  id: string,                    // uid
  bookId: string,
  scope: 'extra' | 'branch',     // extra=番外(独立)；branch=正文分支(附着主线某句后)
  parentChapterIndex: number,    // branch：附着章节
  parentIndex: number,           // branch：附着节拍（该句之后插入选择）
  title: string,
  text: string,                  // 分支正文（段落文本，复用 Engine.buildChapter 分节拍）
  options: [
    { label: string, goto: 'resume'|'chapter'|'story', target: number|string|null }
  ],
  engine: 'offline'|'llm'|'local',
  prompt: string,                // 用户/AI 输入的要求原文
  createdAt: number,
  updatedAt: number,
  schemaVer: 1
}
```

**goto 语义**
- `resume`：回到主线（分支结束默认走这里）。
- `chapter`：跳到主线第 `target` 章（0 基）。
- `story`：进入另一条分支 `target`（storyId），支持链式 → 轻量文字游戏。

### 2.2 Companion（陪伴角色，IDB store `companion`，单例 `id='main'`）

```js
{
  id: 'main',
  name: '阿泠',
  affinity: 0,                   // 亲密度 0~100
  mood: { warmth: 0.6, mischief: 0.3, solemnity: 0.4 },  // 情绪三维 0~1
  flags: { [scene]: { count, lastAt, lastIdx } },        // 场景去重
  history: [ { at, scene, text } ],                       // 最近 20 条
  updatedAt: number,
  schemaVer: 1
}
```

### 2.3 生成器设置（localStorage key `ziliu.generator.v1`）

```js
{
  backend: 'offline'|'llm'|'local',   // 默认 offline
  llm:   { baseURL, apiKey, model },  // 外部 OpenAI 兼容
  local: { baseURL, model },          // 本地 LLM（Ollama 等）
  style: '克制',
  maxTokens: 1200
}
```

### 2.4 存储扩展
- `DB_VER` 1 → 2；新增 `stories`、`companion` 两个 objectStore；**不动** `books`/`progress`，不迁移旧数据。
- 新增方法：`saveStory/getStory/listStories/deleteStory`、`getCompanion/saveCompanion`、`loadGenerator/saveGenerator`。
- 内存降级 `memory` Map 同步扩展 `stories`/`companion`。

## 3. A 段实现规格

### 3.1 分支剧情（`js/stories.js`）

纯函数 API：

```js
XR.Stories = {
  uid(),
  now(),
  normalizeStory(story),          // 补默认字段、校验 scope/goto
  normalizeOption(opt),
  attachChoices(beats, hooks),    // 在 beats 指定位置插入 kind:'choice' 节拍（返回新数组）
  hooksForChapter(stories, chapterIndex)  // 收集某章入口选择钩子
}
```

- `attachChoices`：`hooks=[{index, storyId, options}]`，在 `index+1` 处插入 `{kind:'choice', storyId, options}`；按 index 降序插入避免下标偏移；不改入参。
- `hooksForChapter`：把 `scope==='branch'` 且 `parentChapterIndex===chapterIndex` 的剧情，转成入口选择：`[ {走进岔路→goto:'story'}, {继续读正文→goto:'resume'} ]`。

**运行时导航（ui.js）**
- `S.story = { stack: [], current: null }` 保存返回点。
- 进入分支：压栈 `{chapterIndex, index}` → 用 `Engine.buildChapter({title,text}, 同 opts)` 生成分支 beats → 替换 `S.beats`、`S.index=-1`。
- 分支读到头：弹出 `choiceLayer`，渲染该剧情 `options`（回主线 / 重读 / 去其他分支）。
- `choice` 节拍：`advance()` 遇到 `b.kind==='choice'` 打开 `choiceLayer`，选项 `data-act="choice-pick"` + `data-goto`/`data-target`。

### 3.2 拟人角色「阿泠」（`js/companion.js`）

**人设**
- 名字「阿泠」（lǐng，清凉水声，呼应「字流」）；字流书斋「守卷人」，温润有礼、常年捧卷的书灵。
- 性格：沉稳、温润、书卷气、偶尔俏皮、有仪式感。
- 口癖：「且慢。」「这一页，值得慢慢读。」「来，坐。」「字会替我说。」

**API（纯函数）**
```js
XR.Companion = {
  NAME, defaultState(), normalizeState(state),
  pick(scene, state, ctx, rnd),   // -> { scene, idx, text, moodDelta, affinityDelta }
  chat(topic, state, rnd),        // -> { scene, text, options:[{label,text}], moodDelta, affinityDelta }
  applyDelta(state, res),         // 写回 mood/affinity/flags/history，返回新状态（不改入参）
  SCENES, CHAT
}
```

- 场景：`first-open / add-book / resume / interrupt / goal-chapter / goal-book / goal-pct / branch-entry / idle-chat`。
- 变量替换：`{title}/{chapter}/{chapters}/{pct}/{name}`。
- 去重：`flags[scene].lastIdx` 避免同场景连续重复；`pick` 只读，`applyDelta` 统一推进。
- 情绪/亲密度：`mood` 三维 clamp 0~1；`affinity` clamp 0~100；`history` 保留 20 条。

### 3.3 剧情生成器（`js/generator.js`）

```js
XR.Generator = {
  offline(input, rnd),                     // 默认兜底，纯函数
  buildLLMPayload(input, settings),        // 拼 OpenAI 兼容请求
  parseLLMResult(content, backend),
  generate(input, settings, deps)          // async，deps={fetch,rnd}
}
```

- `offline`：基于书名/章节/风格/要求，模板拼一段番外 + 结尾「回到主线」选项；`rnd` 注入保证确定性。
- `llm` / `local`：OpenAI 兼容 `/chat/completions`；`local` 无 key，默认 `http://localhost:11434/v1`；失败抛错由 UI 提示。
- `input = { title, chapter, context, prompt, scope }`。

## 4. 交互流程

1. **导入书** → `add-book`：阿泠气泡「《书名》归架了，N 章，我记下了。」
2. **打开书** → `resume`：按进度提示「接着第 N 章读」。
3. **读完一章/全书/里程碑** → `goal-chapter / goal-book / goal-pct`。
4. **返回书架** → `interrupt`：「先合上这一页也无妨，书在这里等你。」
5. **读到分支附着点** → 弹出选择（走进岔路 / 继续读正文）；进入后按 `options` 链式跳转，末尾回主线。
6. **点阿泠** → 对话面板：随机闲聊 + 分支对话（书 / 你 / 茶 等话题）。
7. **番外·分支入口** → 列出该书 `extra`/`branch`，可阅读、删除；可「生成新番外」（offline 默认）。

## 6. 第二阶段：云同步 / 朗读 / 书签笔记 / 导出（已实现）

> 默认仍然**全离线**：不配置云端就完全不联网；配置后也只访问你自己的 GitHub 私有仓库。

### 6.0 数据模型改造（`DB_VER 2 → 3`）

| 实体 | 位置 | 字段 |
| --- | --- | --- |
| Book | IDB `books` | 原字段 + `updatedAt`、`deleted`（墓碑：清空 chapters/images，只留元信息） |
| Progress | IDB `progress` | 原字段 + `updatedAt`、`deleted` |
| Bookmark | IDB `bookmarks`（新） | `{ id, bookId, chapterIndex, index, scene, note, createdAt, updatedAt, deleted }` |
| Note | IDB `notes`（新） | `{ id, bookId, chapterIndex, index, quote, text, createdAt, updatedAt, deleted }` |
| Story | IDB `stories` | 原字段 + `updatedAt`、`deleted` |
| SyncState | IDB `sync`（新，单例 `state`） | `{ deviceId, shas, dirty, lastPushAt, lastPullAt, lastError, remoteOnly }` |
| Sync 设置 | `localStorage ziliu.sync.v1` | `{ enabled, owner, repo, branch, dir, token, auto, interval, content, lastAt, lastStatus }` |
| TTS 设置 | `localStorage ziliu.tts.v1` | `{ rate, pitch, volume, voice, follow, scroll }` |

**书 id 改为内容指纹**（`importers.js` 的 `bookKey()`：标题 + 章数 + 首章开头 + 末章结尾 + 作者）。
这样同一本书在另一台设备重新导入会得到**同一个 id**，进度/书签/笔记能直接接上；不同版本（多一章、改过开头）则是不同 id，不会被错误合并。

升级路径：`onupgradeneeded` 里按 `objectStoreNames.contains` 逐个补建，老库只新增 store，不动已有数据；`deleted` / `updatedAt` 缺省时按“未删除、用 addedAt 当时间”处理，老数据无需迁移脚本。

### 6.1 GitHub 云端同步（`js/sync.js`）

**文件布局**（`cfg.dir` 默认 `data`）：

```
data/books.json       书清单（元信息 + 墓碑）
data/progress.json    阅读进度
data/bookmarks.json   书签
data/notes.json       笔记
data/stories.json     番外 / 正文分支
data/companion.json   阿泠的状态
data/settings.json    阅读设置（含朗读设置）
data/content/<bookId>.json   正文（仅当打开「正文也同步」）
```

每个文件都是 `{ app:'ziliu-sync', schema:1, kind, updatedAt, device, items:[…] }`，一个文件一次提交，出问题好回滚。

**首次授权配置**

1. 打开 https://github.com/settings/tokens 生成经典 PAT，勾 `repo`（或 fine-grained 只给目标仓库 Contents 读写）。
2. 建一个**私有**仓库（也可以直接用本仓库）。
3. 阅读设置 → 云同步：填用户名、仓库名、分支（默认 `main`）、目录（默认 `data`）、PAT。
4. 点「测试连接」，看到仓库名即通；再点「立即同步」。
5. 打开「启用同步」。之后启动、联网恢复、每个间隔都会自动跑一次；也可以随时手点。

**推拉与冲突**

- 每个数据集独立 `GET → merge → PUT`：先拉云端，和本地按实体合并，把合并结果写回本地，再推回云端（双向收敛）。
- 合并规则：同一实体比较 `updatedAt`，**新的赢**；时间戳相同则**删除（墓碑）赢**，避免“删了又复活”。
- 不同实体各走各的：书的进度不会因为书签更新而互相覆盖。
- 客户端会记住每个文件的 `sha`；云端被别人刚改过（409/422）时自动重取 sha 再写一次。
- 内容没变就不写（`fingerprint` 比对），避免每 5 分钟制造一条无意义的提交。

**离线策略**

- 本地 IndexedDB 始终是唯一事实来源，断网时阅读、书签、笔记、朗读全部照常。
- 有改动的数据集会打上 `dirty` 标记；同步成功后清除。失败只记录 `lastError`，不阻断阅读。
- 联网（`online` 事件）、下次启动、下个间隔会自动重试；实在同步不了，用「导出全部」做 JSON 兜底。

**安全**

- PAT 明文保存在本机 `localStorage`，不会写进任何请求体，也不会推到云端；换设备需要重新填。
- 建议专用 token + 只给它一个私有仓库；怀疑泄露就去 GitHub 撤销。
- 正文默认不同步；打开「正文也同步」也只传文字，不含插图 dataURL。

### 6.2 本地朗读（`js/tts.js`）

- `speechSynthesis` + `SpeechSynthesisUtterance`，完全本机，不上传文本。
- 朗读单元是 `kind:'line'` 的 `beat.text`；长句按 `normalize()` 清洗后用 `chunk()` 切块，避免浏览器吞长句。
- 读完一句自动读下一句（`follow`）；读到哪句滚到哪句（`scroll`）；`rate / pitch / volume / voice` 全部可调。
- 顶栏 `♪`（快捷键 `T`）开关；朗读时手动翻页会先停下，避免抢节奏；书末自动停。
- 不支持的浏览器（少数 Linux 环境）会提示，而不是静默失败。

### 6.3 书签与笔记

- 顶栏 `✎` 打开「书签与笔记」：`B` 夹书签、`N` 写笔记。
- 位置记 `{chapterIndex, index}`，并抓一句 `scene` / `quote` 作为预览；点条目跳回原文。
- 删除是墓碑，云端同步时别的设备也会一起删掉。

### 6.4 导入 / 导出

- 「导出全部（含正文）」：书清单 + 进度 + 书签 + 笔记 + 番外 + 阿泠 + 设置 + 正文（不含插图）。
- 「只导阅读数据」：给同步/迁移用的小文件。
- 「导入备份」：按 id 合并，已有的书保留正文，只补进度与阅读数据。

## 7. 第三轮：字的手感与英文适配（已实现）

> 这一轮不加新概念，只把「字」本身做扎实：底色不再错位、英文真正可读、字对人有反应。

### 7.1 修掉「字一动、底色就少一截」

**病因**：跳词的底色画在外层 `.kw` 上（`background-image` 渐变 + `inline-block`），而词内部的每个字又各自包了 `.zg` 做位移动画。字一抬起来，底色还钉在原地，于是出现「半边有颜色、半边没有」。

**改法**（三层，缺一不可）：

1. **底色画在词自己身上**：`.kw` 改为 `display:inline` + `::before` 绝对定位的色条（`left/right:0; bottom:.04em; height:.27em`）。词 `white-space:nowrap`，永远只有一段，色条不会跨行撕裂。
2. **词里不再塞会动的字**：`ui.js` 的 `blockedRanges()` 把「跳词 / 搜索命中 / 自定义样式」的区间收集起来交给 `XR.Motion.planLine()`，这些区间一个动点都不放。跳词改用 `data-mv`（`breathe` / `glow`）整词呼吸——字与底色一起明暗，绝不会错色。
3. **自定义样式同样贴字**：`.rx[data-style="hi"]` 从 `background` 改为 `inset` 阴影，跟着字形走。

顺带收紧了 `kw-fresh`（原来是一个 7px 外扩的 box-shadow 环，行内元素上会显示成一个突兀的方块）→ 改成 `text-shadow` 光晕。

### 7.2 英文适配

| 问题 | 改法 |
| --- | --- |
| 逐字 `inline-block` 会让 `well-known` 在词中间断行 | 英文动点改为**整词范围**：`XR.Motion.wordRanges()` 给出 `{s,e}`，`planLine()` 返回带 `end` 的动点，`ui.js` 渲染成一个 `.zg` 包住整词 |
| 句与句拼回去少了空格（`hurry.The`） | `engine.js` 新增 `joinSents()` / `joinSep()`：一侧是 CJK 就直接接，否则补一个空格；`buildSentenceBeats()` 与 `splitLongParagraph()` 都改用它 |
| 中文衬线字体排英文不好看 | `.beat.latin` 用 `--serif-latin`（Iowan / Palatino / Georgia），`letter-spacing:0`、行高 1.66、打开 `font-kerning` 与 `common-ligatures`、`hyphens:auto` |
| 书架把英文书按「字」计数 | `renderShelf()` 改读 `b.lang || b.stats.lang`，英文按 `stats.words` 显示「词」 |

`latin` 判定复用 `XR.Motion.isLatinText()`（拉丁字符 ≥ 4 且多于 CJK 的两倍），和 `engine.js` 里那份判定口径一致。

### 7.3 字会回应你（`js/motion.js`）

纯函数部分（可单测）：

```js
XR.Motion.isLatinText(text)        // 是否以拉丁文为主
XR.Motion.wordRanges(text)         // 英文词边界（don't / well-known 算一个词）
XR.Motion.planLine(text, opts)     // -> { 起点: { end, m, amp, dur, ph, once } }
XR.Motion.pickWordMove(word, rnd)  // 跳词自己的呼吸方式
```

`opts = { level, lead, tone, style, blocked, seed, latin }`：`level` 就是设置里的「拟人动作 关/轻/活」；`blocked` 是高亮区间；`seed` 注入随机源，保证同一段文字每次刷新动法一致。

DOM 部分（`attach({ stage, beats, getLevel })`）：全部只在「有指针 + 未开启减少动态效果 + 拟人动作未关 + 阅读器打开」时生效，且只加类、不改阅读流程。

| 交互 | 触发 | 实现 |
| --- | --- | --- |
| 目光光斑 | 指针在正文上移动 | 写 `--gx/--gy`，`body::before` 画一层 260px 柔光；`elementFromPoint` 找到当前行加 `.lit` |
| 落墨 | 点正文 | `.ink-ripple` 圆环，620ms 后自删 |
| 行的回应 | 点正文 | 被点的 `.beat` 加 `.tapped`，380ms 后移除 |
| 字的火花 | 点跳词 | `.spark` 里最多 6 个字朝四周飞散，900ms 后自删 |
| 字浪 | 按 `Z` | `.beat.wave` 触发 `::after` 的斜向光带扫过 |
| 发呆张望 | 5.2s 无指针、页面可见 | 随机一个可见 `.zg` 加 `.peek`，1.6s 后移除 |
