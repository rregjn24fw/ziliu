# 字流 × Story-to-Game：剧本融合方案

> 基线：`ziliu-源码.zip`（2026-10-23 11:12，含同步坞 / 正文默认同步 / 预填仓库）
> 参照：https://github.com/Shanyin-ai/Story-to-game（JSON 剧本规范 + 单文件启动器 + AI 技能包）

---

## 0. 先定性：不做第二个启动器

| | Story-to-Game 启动器 | 字流 |
| --- | --- | --- |
| 强项 | 剧情结构：节点图 / 变量 / flag / 条件 / 路由 / 结局 / 成就 | 文字质感：活字 / 跳词 / 字的手感 / 朗读 |
| 弱项 | 文字表现只有「段落 + 整段特效」 | 分叉只有内置的几条线，没有真正的状态系统 |
| 形态 | 专门的文字游戏播放器 | 通用阅读器（txt/epub/剧本都能读） |

**结论**：不搬启动器。字流的差异化是「字本身在动」，所以融合方向是
**拿它的结构，用自己的文字表现**——同一份剧本，在字流里既是一本可以读的小说，也是一个可以玩的分支故事。

## 2. 数据映射（剧本 → 字流）

| 剧本字段 | 字流侧 | 说明 |
| --- | --- | --- |
| `segments[].text` | beat（按句切） | 复用现有断句；`speaker` 是系统/旁白 → `tone-soft` |
| `segments[].effect(s)` | 字流动效类 | `shake`→字抖、`glitch`→字错位、`breath`→字呼吸；**只作用于关键词，不是整段** |
| `choices[].text` | 选项行（活字版） | 每行挑 1~2 个字轻微动，点中时字散开重组 |
| `choices[].condition` | 条件求值 | 不满足就不显示（不是置灰） |
| `meta.variableName / val` | 顶部「状态字」 | 不用进度条；「确信」两个字随 val 变粗细/颜色 |
| `ambient` | 页面氛围层 | rain/wind/tide/heat/static → CSS 粒子层，默认关闭、可在设置里关 |
| `scene` | 场景转场 | `major` 换场（一次轻微的黑场），`transient` 不打断 |
| `isEnding` + `type` | 结局页 | TRUE/NORMAL/HIDDEN 用不同收束节奏，`closing` 单独成段慢显 |
| `achievements` | 书架上的成就墙 | 解锁时阿泠说一句 |
| flags / variables | IndexedDB + 云同步 | 和进度、书签同一套存储 |

## 3. 新增模块：`js/storydoc.js`（纯函数，可单测）

```js
XR.Storydoc.parse(json)                 // 校验 + 规范化，返回 { meta, nodes, startNodeId, ... }
XR.Storydoc.assertDoc(doc)              // 13 项结构校验（见 5.2）
XR.Storydoc.initialState(doc)           // { nodeId, val, vars, flags, achievements, visited }
XR.Storydoc.evalCondition(cond, state)  // 字符串 / {all|any|not} 两种写法
XR.Storydoc.resolveNext(node, state)    // routes 顺序求值 → next
XR.Storydoc.applyChoice(doc, state, i)  // val 增减、set、flag、成就、重要决定标签
XR.Storydoc.toBeats(node, doc)          // segments → 字流 beat 数组
XR.Storydoc.progress(doc, state)        // 已访问节点 / 总可达节点
```

约束：**零依赖、无 DOM、CJS 守卫**，和 `engine.js` 同风格，能直接在 `file://` 下跑。

## 4. 超越启动器的五个点（真正的差异化）

1. **逐字特效**：它的 `effect` 作用于整段；字流可以只让「滑」这个字滑出去、其他字稳住。剧本不用改，字流自己挑动点。
2. **跳词即线索**：把现有 `.kw` 用在剧本上——标了线索的词可点，点开给一句提示并记 flag，启动器没有这个交互。
3. **两种读法**：同一剧本可「纯读模式」（无选项，按章节连续读）和「游玩模式」切换。到手先当小说读一遍，再当游戏玩。
4. **朗读剧本**：`T` 键连 segments 带选项一起读，走到选项自动停；启动器没有。
5. **阿泠当 GM**：进入关键分支 / 解锁成就 / 抵达结局时给一句带情绪的反馈；这是已有沉淀，启动器没有。

## 5. AI 生成升级

### 5.1 九步方法论接入 `generator.js`

现在只有 offline 模板。改为：把 SKILL.md 的九步（摄入 → 风格指纹 → 结构拆解 → 状态系统 → 分段写作 → 验证）压成两段 prompt：
- 第一次：只出**方向对齐**（结构、分支比例、结局矩阵），等用户确认
- 第二次：按确认的方向逐章生成节点

### 5.2 校验器移植（`validate.py` → JS）

13 项里最关键的 6 项先做：

| 检查 | 判定 |
| --- | --- |
| 节点可达性 | 从 startNodeId 做 BFS，未被访问的节点报出来 |
| 引用完整性 | 所有 `next` / `routes[].next` / `choices[].next` 必须存在 |
| 死路检测 | 非 `isEnding` 节点必须至少有 choices / next / routes 之一 |
| 结局完整性 | 每个结局必须有 `description` + `closing` |
| 条件语法 | 字符串条件能被解析（不出现拼错的变量名） |
| 支线深度 | 每个结局到起点的最短路径 ≥ N |

生成 → 校验 → 不合格把「哪一行哪个节点错了」回灌重写，最多 3 轮。

## 6. 优先级

| 阶段 | 内容 | 产出 |
| --- | --- | --- |
| **P0** | `storydoc.js`（解析/状态机/条件/路由）+ 单测 | 能用代码跑通「成人日」361 节点 |
| **P0** | 导入 `.json` 剧本（拖进书架）+ 阅读器接入 + 选项渲染 | 能在字流里玩完整一本 |
| **P0** | 结局页 + 成就面板 | 有「玩完」的收束感 |
| **P1** | 存档落库（val/vars/flags/结局/成就）+ 云同步 | 换设备接着玩 |
| **P1** | ambient / 逐字特效 / 跳词线索 | 观感差异拉开 |
| **P2** | 朗读剧本、阿泠 GM、AI 生成 + 校验闭环 | 完整体验 |
| **P2** | 剧本调试面板（跳节点/看变量/改 flag） | 写剧本时自用 |

**验收口径**（沿用现有习惯）：
- `selftest` 新增 `[16] 剧本` 段：条件求值、路由顺序、val 钳制、存档往返、坏 JSON 不炸
- `interact-test` 新增：拖入剧本 → 书架出现「可玩」角标 → 进第一节点 → 点选项 → 抵达结局

## 7. 不做什么

- **不引框架、不引构建**：保持零依赖、`file://` 直开。
- **不搬启动器的全部特效**：字流的调性是克制，特效只给关键句，不给每段。
- **不破坏默认离线**：剧本本地解析，AI 生成仍需用户显式开启。
- **不做脚本编辑器**：写剧本继续交给 Story-to-Game 的 AI 技能，字流只负责「读」和「玩」。
